# X, the platform

X is a sphere, not one switch. The public network, the ad system, the client, the hosted model, and the money product sit in one company and fail in different places. Open code that matters: [xai-org/x-algorithm](https://github.com/xai-org/x-algorithm) (For You, Apache-2.0, moving as of 5 November 2026), the earlier [twitter/the-algorithm](https://github.com/twitter/the-algorithm), [twitter/communitynotes](https://github.com/twitter/communitynotes), and [xdevplatform/chat-xdk](https://github.com/xdevplatform/chat-xdk) for chat encryption. No public repository named X Money was found. The product page is [money.x.com](https://money.x.com), read on 10 November 2026. Hosted Grok is the [xAI](07-xai.md) page.

Opening the ranking code removed a secrecy advantage. It did not remove the operator. The feed, the account, and the ad auction still run on X's servers. X Money adds a second operator, a bank, beside that one.

## The sphere

**Speech.** Posts, accounts, and removal orders land on X. One operator, many courts.

**Ranking and notes.** The For You code and Community Notes are public. The live feed and the live corpus are still X's.

**Ads and subscriptions.** The auction and the paid plans are X's ledger. An advertiser can refuse to spend. That refusal is not a freeze of someone else's coins.

**Chat.** The encryption SDK is public. The ciphertext is not a candidate for this rail.

**Grok on X.** The model that answers inside the app is hosted. The account switch is on the xAI page. This page does not move prompts onto a chain.

**X Money.** A dollar balance, a card, and a transfer between handles. This is the payment exercise below. It is not a Kaspa product, and this study does not claim X asked for one.

## 1. Exposure

**Accounts and posts.** X can suspend an account. A court can order X to remove speech or to identify a user. The rail does not put a suspended account back on X, and it is not a tool for ignoring an order to remove illegal content. Speech that is only stored on X disappears from X when X removes it. That is the exposure: one operator, worldwide, with different courts pulling on the same switch.

**Money.** [money.x.com](https://money.x.com), read on 10 November 2026, offers a balance inside the app to select users in the United States who are 18 or older. The same page says X Payments LLC is not an FDIC-insured bank. Deposit accounts are held at Cross River Bank, Member FDIC, and other insured banks through a cash sweep. The card runs on Visa. Yield and cashback vary by plan and by place. New York residents, on that page, do not receive yield. [Cross River's announcement](https://apnews.com/press-release/business-wire/press-release-3bf5f4b748694a98a52eff96a674b2a4) of 27 July 2026 says it powers those accounts and the card. [The Verge](https://www.theverge.com/tech/971649/x-money-launch-elon-musk), the same day, reported the rollout beginning with Premium and Premium Plus subscribers in the US.

That balance has more offices than the feed. The bank can be ordered. Visa can be ordered. A money-transmitter license is a state switch, and this page did not read the dockets, so it does not print a count of them. Reporting in September 2026 said US creator payouts were moved onto X Money and that creators outside the US stayed on the previous processor. This page did not open the creator help article, so that sentence stays a report. On 25 October 2026 Musk wrote that a long press on like would send one dollar via X Money. The product page read for this pass does not describe that gesture, so this page does not treat it as shipped.

A public KAS payment between a willing viewer and a willing creator has no processor and no bank. Distribution on X is still X's. The dollar inside X Money is not that payment. It is a bank dollar wearing the app's name.

**The record of a Community Notes run.** The algorithm is public. The claim "this output came from this input under this code" is not, unless someone seals both hashes. A notes corpus hosted on one site can be taken down or edited. The code repo can remain while the snapshot is gone.

**Chat.** [chat-xdk](https://github.com/xdevplatform/chat-xdk) is an encryption SDK. Ciphertext and keys belong to the conversants. A public sequencer is a bad archive for either.

## 2. Worth exploring

**Notes seals.** After a published Community Notes scoring run, seal the hash of the input snapshot and the hash of the output ranking. Anyone with the snapshot can check the open code against the claimed output. X does not have to do this. A mirror, a journalist, or an engineer can. If the dataset host in one country is blocked, the digest remains.

**Creator payments in KAS, beside X Money.** A creator can publish a `kaspa:` address next to the handle. A viewer can pay it. No integration, no marketplace contract, no freeze key at X Payments or at Cross River. The platform can still demonetize, downrank, or suspend, and X Money can still refuse a payout into the in-app balance. The KAS payment that already settled does not unsettle. This is an improvement for people who want it, not a feature X must ship, and not a replacement for the Visa card. A tip that is only a gesture inside X Money is still the bank dollar.

**Ranking code seals.** Seal the git tag of `x-algorithm` when a public claim is made that the live feed matches a tag. The seal does not prove the servers ran that tag. It proves which tag was named, and when. Proving the servers ran it is a hosting question, not a consensus question.

Do not put the For You graph, follower lists, or ad-conversion logs on the chain. Transparency of the code is already the public artifact. Transparency of user behavior would be a new harm.

## 3. While miners mine

A notes digest and a KAS payment have no trust-and-safety desk and no acquiring bank. They continue while miners mine, including in a country that has blocked x.com, for anyone who can still reach a node.

The feed does not continue. The account does not continue. An order served on X still binds X. People who need the public square of X remain dependent on X. People who need a receipt or a payment have a second rail that X does not operate.

## Dollar, still a draft

X Money is the dollar surface that already has a name, and it fails the test this study is running. The balance can be reached through the bank, the card network, and the company that operates the app. [Kaspa Dollar](../DOLLAR.md) is the draft of a different unit: no company key that claws it back after it has moved, collateral still KAS, redeemed as KAS. An advertiser can still refuse to spend. A creator payout that X chooses to send through X Money is not that draft. A viewer who pays the draft unit, if it ever exists and both sides want it, is paying beside the app. The fee on that transfer is the Kaspa mass rate, 100 sompi per gram in v2.1.0, not a slice of the tip. The X Money page says a transfer to someone on X is free, so this path does not undercut that advertised transfer. It undercuts a card or a wire, once the unit exists. The draft does not host a post, clear an auction, keep an account open, or insure a deposit. The feed stays X's. The design is a draft. It is not a coin yet. The fee path is written in [DOLLAR.md](../DOLLAR.md).

## Space watts

The post is already public on X. Sealing its text orders a copy of a sentence the platform already showed. It does not move a watt. X Money does not finance an array. The lenses are in [WATTS.md](../WATTS.md). Whether a node is the best tool on this branch is [NODE.md](../NODE.md).

## What this rail does not do

It does not host posts, rank a feed, clear an ad auction, or reverse a lawful removal. It does not encrypt chat better than the chat SDK. It does not make the balance inside X Money uncensorable. That balance is held at a bank. X Payments LLC, on the product page, is not that bank. The rail does not custody dollars, does not issue the card, and does not move FDIC insurance onto miners.

## Detail

A Community Notes run that someone chooses to publish is an eval seal with two hashes.

```rust
let payload = kaspa_seal::encode_seal(&kaspa_seal::Seal {
    branch: kaspa_seal::Branch::X,
    kind: kaspa_seal::Kind::Eval,
    primary: kaspa_seal::document_hash(input_snapshot),
    aux: Some(kaspa_seal::document_hash(output_ranking)),
});
```

Anyone with both files checks them against bytes 17..49 and 49..81. Bit 0 of byte 16 is set because `aux` is present. The open code in [twitter/communitynotes](https://github.com/twitter/communitynotes) is how a verifier reruns the scoring. The chain does not rerun it. [KIP-16](https://github.com/kaspanet/kips/blob/master/kip-0016.md) could verify a proof of a program only if that proof was actually produced for tag `0x20` or `0x21` and the public inputs were the hashes. No such proof is claimed here. The live object is the seal.

A claim that the live feed matches a git tag is `Kind::PublicFile` over the tag name or the commit id the speaker published. The hash fixes which string was sealed. It does not inspect X's servers. Proving a server ran a binary is a hosting question.

Creator payments on this rail are the escrow or a plain KAS transfer. The escrow is a single-input example that trusts the arbiter. It binds the coins to a document hash, checks one output, and has no timeout. A tip that needs no document does not need the covenant. Either way the unit is KAS. X Money is the other exercise: a dollar ledger inside the app, bank at Cross River, card on Visa, as the product page states it. The two are not the same payment. A profile can show both a handle for X Money and a `kaspa:` address. Only the second one is outside the bank.

The For You graph, follower lists, ad logs, chat ciphertext, and chat keys are not hash inputs. [x-algorithm](https://github.com/xai-org/x-algorithm) being public is the disclosure. Hashing user behavior would publish a new file. The payload rules and the test vectors are in [the code notes](../code/BYTES.md).
